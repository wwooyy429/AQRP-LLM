## 四项交付及证据边界

G1是固定新版Research、联合历史采集/缓存及LEAN的真实成功链。编译、提交、平台完成和工程检查合格分别记录；只有真实原生终态、完整工程报告、身份匹配且必需检查全过才能由Registry记completed。空宿主退出和手写passed不合格。

G2增加共享的受控worker诊断。冻结部署严格哈希合同不放宽：保留EOF，UTF-8-sig及通用换行处理不变，同一次文件读取生成期望/实际hash及格式、导入和路径指纹等白名单观察。诊断不输出源码、绝对路径、市场值或系统异常。当前源码引用匹配不是worker认证；新worker观察也不能追认旧75失败的实际字节或根因。未经证据不通过忽略导入或尾部空白来消除失败。

G3实现Research原生异常的固定解析和恢复。派发前生成固定cell，对惰性输入做原字节hash校验，清除长驻kernel中的旧共享模块缓存。实际read_cell的源代码、项目及index必须匹配，才可保存新任务的不可变执行绑定。只有明确的原生error节点及完全匹配的预先绑定才可结算失败；网络/超时、未知封装、成功cell内捕获异常都不能替代。旧任务恢复不能事后补新协议。同失败回执幂等，矛盾回执拒绝，未知执行不能重跑。

G4补充固定程序的证据型数据审计。范围、预热、预期交易日、永久SID、历史资格、20完整交易日流动性排名、历史成员、RAW行情、映射/公司行动和财务版本/时间需显式绑定。缺失保持缺失，不用当前股票名单回填，不因财务缺失换入第201名。仅有Time/EndTime、近似FileDate或本次摄入时间不足以认证过去实际公开、供应商送达及历史摄入。没有可信来源协议时，字段时序符合规则也不能使正式数据认证为true。

## 开发侧顺序

1. 在同一共享库集中实现模块及独立构造的合成边界/已知答案测试；记录首次失败和修正，不调用市场执行接口。
2. 使用 `python -B tools/research.py build` 生成部署配置，再用 `python -B tools/stages.py verify` 完整离线验证。生成文件不手改，结果只属开发侧软件证据。
3. 先列QC项目，仅使用列表返回的ID；部署后逐文件读回实现，检查完整受管文件集合、固定输入及编译。尽量在登记最后一个工程配置之前解决上传、大小和语法问题，不通过新项目绕过额度或未知任务。
4. 冻结完整联合工程计划，先登记配置和claim Research，再prepare并上传固定输入/cell；通过实际read_cell校验取得一次性派发许可。实际调用前再次确认身份及预算；许可重复读取不授权重跑。
5. 实际Research一次运行2018年AAPL/MSFT RAW缓存检查及美东[2018-01-01,2018-02-10)的40日历史快照观察。共享缓存重复读取新增History请求须为0；值和逐行结果只在QC Cloud，回执只含许可元数据。
6. 只有合格Research完成证据才准入LEAN。预扣、prepare及核对新输入后只提交一次零订单回测，保存实际backtest ID并等待异步完成交付，不轮询待完成任务。收到终态后解析完整工程日志及报告，成功和失败均按原attempt入账。
7. 汇总实际运行、受控诊断、原生异常链和数据审计证据，冻结交付版本供统一独立验收。来源缺失仍列证据不足，不制作替代回执。
