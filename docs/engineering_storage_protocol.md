# 阶段2缓存与容量修复协议

本协议只验证2018年AAPL/MSFT数据管道，不生成经济因子、不下单。正式研究、自动GPT API、交易和最终测试仍关闭；2024–2025暴露记录不变。

配置周期重置采用追加授权事件：保留累计使用量、旧周期、关闭轮次和失败记录，当前周期单独限制13个配置（正常8、预留5）。Research20及LEAN16的总上限和累计使用量不重置。登记、执行前分别扣额，失败不退还。

采集缓存数据身份由数据版本、字段定义、时间边界和固定处理语义组成，与计划名称和无关源码变更分离。旧完整缓存仅在处理语义一致、原回执、全部40窗口及每批哈希均验证后复用；不复制、不重命名旧行，也不补取缺失窗。原来源身份留在新元数据回执内。

schema4的Research仅从既有价格和股票池缓存读取，不调用History。LEAN实际接收OHLCV后，按SID、字段、事件时点、可用时点、版本和值逐项比较同窗口缓存；同时验证原五个字段缓存对象的内容哈希。只有全部相同才保存可读JSON引用清单，包括请求、窗口、行数、行集合哈希与原缓存引用，不再次保存行值。缺少、重复、额外、改值或可用时点不一致均拒绝。

写入前必须从SDK取得容量、文件数和所有现有对象的稳定文件长度，预留冻结的字节和文件数余量。元数据缺失、发生并发变化、SDK错误或容量不足均在取数和新写入前停止。该预检是单一写入者下的时点检查，不是跨进程预留锁。接收清单在最终写入前再次按实际JSON大小检查。

错误日志仅输出固定步骤、错误类别和白名单代码，不输出原生异常消息、路径、行值或第三方任意类型名。保留内部错误与保存拒绝、容量不足、读回校验失败的区分；不伪造成功回执。

旧schema1/2执行规则不改。schema3计划和回执元数据只为历史解析和重放保留，当前worker明确拒绝执行。轮次006因QuantConnect拒绝压缩包导入而关闭，已用配置不退款，Research及LEAN未执行。schema4不导入或调用任何压缩器，不绕过平台源文件限制。

离线验证命令为`python -B tools/stages.py verify`，使用合成数据且不得访问市场供应商。开发测试或一次云端样例成功均不等于阶段2整体验收；完整历史US200、财务版本与实际公开/送达/摄入时间凭证仍须分别认证，并由GPT Work审核固定提交。

轮次007在执行前遇到另一原生限制：registry.py超过60800字符。该轮关闭、配置不退还，Research/LEAN均未执行。新轮008按职责拆分可读模块，保留原API和错误类身份；冻结/扣额前按已观测的原生单文件字符上限检查全部源文件，动态任务输入在首次发布前同样检查。此检查不等于编译或运行成功；平台规则仍为最终边界。
