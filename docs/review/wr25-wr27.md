## WR-25：分类采用封闭语义

`UNMAPPED_VENDOR_CODE`、未知代码或拼写错误不能仅因不属于INCLUDED就被当作明确排除。观测审计复用上游登记的封闭分类集合，将资格分为纳入、明确排除、未知；未知不能借全缺流动性和第201名补位通过。明确当时已知的未上市状态或登记过的排除类别保持合法排除，None不被伪装为已知分类。原记录、引用和私有汇总重核保持。

## WR-26：已知历史SID必须有当前资格覆盖

资格检查同时核对形成时点可知的历史SID及其当前记录，不只遍历已有active行。旧映射区间结束不等于证券退市；当前区间缺失或晚于形成时点才可知时保留未知，不能从完整性循环中消失，也不能读取未来值回填。明确、及时的排除记录可排除；仅未来才出现且此前没有已知证据的SID不会被当作过去已知库存。

复验应把纳入／排除／未知分类、当前记录齐全／缺失／未来可知、流动性齐全／单期缺失／全缺联合检查。原IPO20期、连续主表、未知状态、断档／重叠、原refs／raw／count和正式认证false边界均需保持。

## WR-27：所有检查绑定同一目标目录

显式 `--root T` 时，元数据、Git差异、预算、账本、历史描述和source清单均应针对T计算，不能混用工具所在S的源码哈希。默认目录行为保持，不通过切换cwd或修改模块全局ROOT实现。跨目录正控必须在目标树的源码确实不同且变更列表正确的条件下检查：正确T哈希通过，外来S哈希拒绝；调用后默认S身份不受污染。

规定离线入口为 `python -B tools/research.py build`、`python -B tools/stages.py verify`，最终元数据更新后运行 `python -B tools/review_metadata.py`。开发记录、原反例、首次失败／夹具适配、最终源码身份与结果见 `audit/review_packages/wr25_wr27/`。不同版本及有重叠套件分开记录，不累加为独有检查数。
